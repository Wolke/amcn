## 機器 2 要做的事（三行）

```bash
brew install tor          # 或 sudo apt install tor
git clone https://github.com/Wolke/amcn.git && cd amcn/node
./join.sh                 # 先 ./join.sh --check 看它要連去哪
```

`join.sh` 會：檢查 Node ≥ 20 → 起本機 tor（只當客戶端）→ 產生並保存身分
（`configs/.verifier-seed`，0600）→ 經 onion 註冊 → 開始接驗收工作。
`./join.sh status` 看狀態、`./join.sh stop` 停掉。

**先只當驗收者**。它不需要 API key、不需要模型、不參與信用，所以第一趟要量的是
連線而不是經濟。

## 三個階段，每一段都有一個**要量的數字**

### 階段 1：連得上（30 分鐘）

| 量什麼 | 怎麼看 | 機器 1 實測的參考值 |
|---|---|---|
| 第一次建電路的時間 | `join.sh` 到 `registered as verifier` 的間隔 | 同機 2.1 s；跨機**未知** |
| 取一次帳的時間 | `AMCN_TRANSPORT=tor node ledger-dump.js out/mine.json <onion> 47180` | 同機 14.1 s（含建電路）、331 KB |
| 自己驗那本帳 | `node verify-ledger.js out/mine.json --pin did:demo:634d724a19976c95` | 應該看到「通過」與 Σ=0 |
| 長連線穩不穩 | 掛 30 分鐘，數 `disconnected` 出現幾次 | **這是 #86 真正沒有資料的那一格** |

斷線會自己重連（#40），所以要看的不是「有沒有斷」而是「斷了多久、會不會自己回來」。

### 階段 2：賺到第一筆 CC（看運氣，可能要等）

機器 2 是**從沒收過 CC 的身分**，所以它是入門採購（#90）唯一合格的對象——
機器 1 的發樁者每分鐘發一次「答案已知的工作」，連續 3 次通過才付一次，每身分上限
20 CC。

**但驗收者接不到那種任務**：入門採購買的是**交付**，要能出價就得有 adapter。
所以想讓它賺到第一筆，機器 2 要用 mock adapter 當供給端：

```bash
cp configs/provider.example.json configs/m2.json
# 編輯：name 改掉；adapter 全部留 null（mock，不花錢也不需要 key）
#       provide.afterMs = 0、pricePerUnit = 1.0
AMCN_TRANSPORT=tor AMCN_PROVIDER_KEY=sk-m2-mock node agent.js configs/m2.json
```

要量的：**第一筆 `SETTLED` 出現在機器 1 的 log 裡**，以及機器 2 的餘額從 0 變正。

> **誠實標註（#103）**：入門採購目前的題目是算 sha256，那不需要模型也不花錢。
> 所以這一段證明的是**流程**（新人能賺到第一筆、連續 3 次的門檻有效、治理上限
> 有在扣），**不證明**反 Sybil——那要等題目變成真的要花算力。全網上限已經壓到
> 200 CC 就是因為這個。

### 階段 3：真的買賣一次（需要機器 1 已上工）

機器 1 執行 `./service/arm-supply.sh` 之後才有真實算力可賣。然後在機器 2 上用
MCP 或 Console 發一筆**真實需求**的任務（弱斷言：`max_len`＋`contains`，因為真
模型的輸出不是確定性的）。

要量的三件事：成交、機器 1 的 `[owner]` 那一行（用掉多少 token、還剩多少）、
以及機器 2 的餘額變負（它借了算力）。**那一筆就是 §27 閉環的第一次跨機器實現。**

## 會出問題的地方（先知道就不會誤判）

| 症狀 | 成因 | 怎麼確認 |
|---|---|---|
| `join.sh` 說找不到 tor | 沒裝 | 它會直接給你安裝指令，而且**不會啟動任何東西** |
| 一直 `rendezvous/連線` 失敗 | onion 電路建不起來（網路封鎖 tor） | `AMCN_TRANSPORT=tor node ledger-dump.js …` 單獨試一次 |
| 註冊成功但收不到驗收工作 | panel 已經有 3 個（機器 1 的），抽選不一定抽到你 | 機器 1 的 log 會顯示 pool 大小；這是正常的 |
| 出價了但從不得標 | 沒有 adapter（#21：不能執行者不得出價），或價格比機器 1 高 | agent 啟動時會說 `supply NOT armed: …` |
| 餘額一直是 0 | 網路上沒有需求——機器 1 的供給端 `posts: 0` | 這不是 bug，是市場狀態（#100） |

## 這一趟**之後**才誠實的說法

- **可以說**：「兩台機器、不同故障域、經 onion 完成借用→驗收→結算」——如果階段 3 成立。
- **不能說**：「有市場需求」。機器 2 若是你的，每一筆仍是 `related-party`（#63），
  而報表要把它與 `market` 分開列。
- **仍然沒有**：地理上真正分開的兩地（如果兩台都在同一個網段，#86 只關掉一半）、
  四小時拔線演練、以及第三方 panel（#31：驗收者仍全在機器 1）。
