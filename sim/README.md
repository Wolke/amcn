# AMCN Phase 0 經濟模擬器

對應 SDD §19 Phase 0：**單機經濟模擬**。不呼叫任何真實付費模型，用途是在寫任何協議程式之前，先證偽（或支持）SDD §26 的高風險經濟假設。

## 執行

```bash
cd sim
python3 -m amcn_sim --agents 500 --days 84 --scenario baseline
python3 -m amcn_sim --all-scenarios          # 跑全部情境並輸出比較
```

無第三方相依，Python 3.10+。結果輸出到 `sim/out/<scenario>_summary.json` 與 `<scenario>_daily.csv`。

## 情境

| 情境 | 用途 | 對應 SDD |
|---|---|---|
| `baseline` | 一般市場：2% deadbeat、2% 洗量 | §19 |
| `expiry_cliff` | 所有額度同日重置 → 測月底到期價格崩跌 | §14.4 |
| `high_default` | 15% 參與者借滿信用額度後永久離線 | §16 威脅 13 |
| `wash_heavy` | 20% 參與者成對洗量 → 測 FR-061/062 多樣性折減 | §14.4、§16 威脅 7 |

## 模型摘要

- 1 tick = 1 小時；1 CC ≈ 1 個抽象 compute unit 的參考價值。
- 每個 Agent 有：額度容量與計費週期（未用即到期）、日常消耗分布、突發需求（UC-01 觸發器）、可靠度/品質、Owner 定價政策與目標餘額區間。
- 額度耗盡 → 在信用額度內發布任務借用（UC-01）；額度重置且餘額低於目標 → 降價供應還債（UC-02）；額度接近到期且預估浪費 → 自動折價（UC-03）。
- 帳本為嚴格雙式記帳：每組 posting 總和必為 0，全部餘額可由事件重建（FR-050/051、NFR-006）。手續費 2.5% 入 `protocol:treasury`；壞帳沖銷入 `protocol:loss`（本身轉負，維持 Σ=0）。
- 信用額度演算法（§14.3）：`f(帳齡, 多樣性折減後貢獻, 完成率, 對手方多樣性, 爭議率)`，起始額度 20 CC，上限 500 CC。同一對手方超過總量 25% 的部分不計入貢獻（FR-062，洗量成本）。
- 驗收簡化為 Bernoulli(可靠度×品質)；失敗＝不結算＋記一次爭議（FR-051）。

## 輸出指標（§19 要求）

成交率、任務等待時間（平均/P95）、餘額 Gini、還債週期（負餘額→回正的天數）、壞帳率（沖銷 CC / 總結算 CC）、Credit velocity（月結算量 / 未償債務）、洗量佔比、誠實 vs 洗量 Agent 的信用額度對照、首週 vs 末週價格（到期崩價訊號）。

## 已知簡化（誠實聲明，SDD §22.18）

- 批次撮合而非非同步 P2P 競標；無議價回合。
- 無網路延遲、分割與節點暫時離線。
- 驗收品質無 Judge quorum 模型，無串謀 Verifier。
- 價格策略是規則式，不是學習型 Agent；真實 Agent 議價行為可能更極端。
- Deadbeat 的「最後一把梭」行為是保守上界假設。
